개인정보처리방침

이 방침은 Usage Pocket iOS 앱과 위젯, 이 안내 페이지에 적용됩니다. 운영 명칭은 Usage Pocket이며 개인정보 관련 문의처는 lhyundong.kiml@gmail.com입니다.

사용자 각자가 자신의 iPhone에서 본인 계정을 직접 연결합니다. 운영자는 앱을 통해 AI 계정 정보, 비밀번호, API 키, 로그인 세션·토큰 또는 사용량을 전달받거나 수집·취합하지 않습니다. 인증과 조회를 중계하는 운영자 서버도 없습니다.

다만 연결한 AI 서비스와 로그인 제공자는 요청을 직접 받으며, Google AdMob은 배너 광고를 위해 별도의 정보를 처리할 수 있습니다. 따라서 이 앱의 모든 외부 데이터 처리가 없다는 의미는 아닙니다.

1. 서비스 연결 및 사용량 조회

  • OpenRouter: 사용자가 입력한 API 키로 기기에서 OpenRouter에 직접 HTTPS 요청을 보내 일반 키의 사용액·한도를 조회합니다. 관리 키를 연결하면 계정 전체의 최근 완료된 30일 비용, 입력·출력·캐시 토큰, 요청 수와 모델별 집계를 조회합니다. 키는 검증 후 이 기기의 Apple Keychain에 저장됩니다. 사용량 조회 기능은 AI 생성 요청을 보내지 않습니다.
  • OpenAI API·Claude API: 사용자가 입력한 본인 조직의 관리자 API 키를 각 제공사의 공식 HTTPS API로 직접 보내 이번 달 조직 전체 비용·일별 비용과 제공되는 모델별 입력·출력·캐시 토큰 및 요청 수 집계를 조회합니다. 검증된 키는 서비스별 기기 한정 Keychain 항목으로 저장됩니다. 일반 모델 호출용 키와 구독 로그인은 이 비용 조회에 사용하지 않으며, AI 생성이나 계정 변경 요청을 보내지 않습니다.
  • Codex·Claude: 사용자가 앱 내 공식 웹 로그인 화면에서 직접 로그인합니다. 로그인 쿠키·웹 세션은 서비스별로 분리된 기기 내 WebKit 저장소에 유지되고 사용량 조회에 사용됩니다. 앱은 Safari의 기존 쿠키를 가져오지 않습니다. 선택한 로그인 제공자의 화면에는 해당 제공자의 개인정보처리방침이 적용됩니다.
  • 조회 결과: 서비스 이름, 한도 및 남은 비율, 한도 재설정 시각, API 서비스 사용액과 일별 비용, 모델 이름과 날짜별 토큰·요청 수 집계, 조회 시각, 연결 상태와 계정 구분용 해시값을 기기에 저장합니다. Claude 조직 선택이 필요한 경우 조직 이름과 식별자를 선택·조회에 사용하고, 저장 시 계정 참조값을 해시 처리합니다.
  • 사용량 조회 기능은 프롬프트나 대화 내용을 수집·저장하는 기능이 아닙니다. 공식 웹페이지를 직접 탐색할 때 해당 웹사이트가 처리하는 정보에는 그 사이트의 방침이 적용됩니다. Gemini 자동 사용량 연결은 현재 제공하지 않습니다.

2. 기기 저장소와 위젯

사용량 기록, 연결 상태, 언어, 색상 및 자동 기록 설정은 기기 내 앱 저장소에 보관됩니다. 위젯은 같은 기기의 공유 저장소에서 저장된 사용량을 읽으며, 별도로 서비스에 로그인하거나 광고를 표시하지 않습니다. Usage Pocket 자체 계정, 운영자 데이터베이스 또는 자체 클라우드 동기화는 없습니다. 기기 백업·복원 여부는 iOS와 사용자의 백업 설정에 따라 달라질 수 있으며, API 키는 서비스별 기기 한정 Keychain 항목으로 저장합니다.

자동 기록을 켜면 iOS가 허용하는 시점에 기기에서 연결한 서비스로 직접 사용량을 조회할 수 있습니다. 실행 간격은 보장되지 않습니다. 조회 결과와 함께 시도·성공 시각, 처리 단계, 오류 유형, 응답 상태 코드, 소요 시간 등 최소한의 진단 정보가 기기에 저장됩니다. 진단 정보에 비밀번호, 쿠키, 토큰, 인증 코드 또는 대화 내용은 포함하지 않습니다. 설정의 자동 기록에서 수집을 끌 수 있습니다.

3. 배너 광고와 개인정보 선택

홈 화면 하단의 배너에는 Google AdMob(Google Mobile Ads SDK)을, 동의 메시지와 광고 개인정보 선택에는 Google User Messaging Platform(UMP)을 사용합니다.

광고 서비스는 IP 주소와 이로부터 추정되는 대략적 위치, 기기·앱 관련 식별자, 광고 노출·클릭 등의 상호작용, 성능 및 오류·진단 정보, 동의 상태를 처리할 수 있습니다. 이 정보는 광고 제공·측정, 분석, 문제 해결과 부정 이용 방지 등에 사용될 수 있으며 Google과 동의 화면에 표시되는 해당 광고 파트너의 정책이 적용됩니다.

현재 앱은 비개인화 광고를 요청하고 Google 게시자 퍼스트 파티 ID를 비활성화하며, 광고 식별자(IDFA)에 대한 추적 권한을 요청하지 않습니다. 비개인화 광고도 위와 같은 데이터 처리가 발생할 수 있습니다. AI 계정 정보, API 키, 로그인 세션·토큰 및 사용량을 광고 요청이나 광고 SDK에 제공하지 않습니다.

필요한 지역에서는 동의 화면에서 선택할 수 있습니다. 앱 설정에 광고 개인정보 설정이 표시되면 이를 열어 선택을 변경하거나 동의를 철회할 수 있습니다. 광고 요청 가능 여부는 UMP의 판단을 따릅니다. 동의 확인 오류로 광고를 요청할 수 없는 경우 광고를 생략하며 서비스 연결·조회는 계속 이용할 수 있습니다.

5. 보관 기간과 삭제

  • 사용량 기록: 성공적으로 새로 조회할 때 최근 90일 범위로 정리하며, 저장 개수에도 상한을 적용합니다. 전경 또는 백그라운드에서 조회에 성공하지 않으면 이 정리 작업은 실행되지 않습니다. 설정의 저장된 기록 삭제로 기록을 지울 수 있습니다. 이 동작은 현재 연결과 최신 조회값을 유지합니다.
  • API 연결: 설정이나 서비스 상세에서 연결을 해제하면 앱에 저장된 키, 해당 연결의 최신 사용량과 기록을 삭제합니다. 제공사 자체의 키를 폐기하려면 해당 제공사에서 별도로 취소해야 합니다.
  • Codex·Claude: 서비스 연결 해제 시 해당 서비스의 저장된 사용량, 기록과 앱 내 웹 로그인 데이터를 삭제합니다. 로그인 화면의 이 서비스의 웹 로그인 초기화로 웹 로그인 데이터만 지울 수도 있습니다. 제공자 계정과 다른 앱의 로그인은 삭제되지 않습니다.
  • 최신 조회값과 설정은 삭제·변경 전까지 기기에 남을 수 있습니다. 앱 삭제만으로 모든 Keychain 항목이 삭제된다고 보장할 수 없으므로, 삭제 전 연결 해제를 이용해 주세요. 백업 사본은 사용 중인 백업 서비스에서 관리해야 합니다.
  • Google·AI 서비스가 직접 보유한 데이터의 삭제와 보관은 해당 제공자에게 요청해야 합니다. 운영자는 기기에만 저장된 데이터에 원격으로 접근하거나 이를 삭제할 수 없습니다.

Privacy Policy

This policy covers the Usage Pocket iOS app, its widgets, and this information page. The operator uses the name Usage Pocket. For privacy questions, contact lhyundong.kiml@gmail.com.

Each user connects their own accounts directly on their own iPhone. The operator does not receive, collect, or aggregate AI account details, passwords, API keys, sign-in sessions or tokens, or usage data through the app. There is no operator server that proxies authentication or usage requests.

Connected AI services and sign-in providers receive requests directly. Google AdMob may separately process data to deliver banner ads. This does not mean that the app involves no external data processing.

1. Service connections and usage requests

  • OpenRouter: Your device sends your entered API key directly to OpenRouter over HTTPS to retrieve a regular key’s spending and configured limit. With a management key, it retrieves account-wide costs, input/output/cache tokens, request counts and model breakdowns for the last 30 completed days. After verification, the key is stored in Apple Keychain on this device. The usage lookup feature does not send AI generation requests.
  • OpenAI API and Claude API: Your device sends your own organization Admin API key directly to the provider’s official HTTPS API to retrieve organization-wide current-month and daily cost reports, plus available model-level input/output/cache token and request-count aggregates. Verified keys are stored in separate device-only Keychain items. Standard model keys and subscription sign-ins are not used for this report. The app does not make AI generation requests or account changes.
  • Codex and Claude: You sign in yourself on the service’s official web sign-in page within the app. Cookies and web sessions remain in separate, per-service WebKit stores on your device and are used for usage requests. The app does not import existing Safari cookies. Any sign-in provider you select processes information under its own policy.
  • Results: The app stores service names, quota and remaining percentages, reset times, API spending and daily cost reports, model names and daily token/request aggregates, observation times, connection status, and hashed account references on your device. If Claude organization selection is needed, organization names and identifiers are used for selection and requests; the stored account reference is hashed.
  • The usage lookup feature does not collect or store prompts or conversation content. Information processed while you browse an official service webpage is subject to that website’s policy. Automatic Gemini usage integration is not currently provided.

2. Device storage and widgets

Usage history, connection status, language, colors, and automatic recording preferences are stored locally. Widgets read saved usage from a shared container on the same device; they do not independently sign in to services or display ads. There is no Usage Pocket account, operator database, or app-operated cloud sync. Device backup and restoration may depend on iOS and your backup settings. API keys use separate device-only Keychain items.

When automatic recording is enabled, the device may query connected services directly when iOS permits. Refresh intervals are not guaranteed. Minimal diagnostics such as attempt/success times, processing phase, error type, response status code, and duration are stored on the device alongside collection results. Diagnostics do not include passwords, cookies, tokens, authentication codes, or conversations. You can disable collection in Settings > Automatic recording.

3. Banner advertising and privacy choices

A banner at the bottom of the home screen uses Google AdMob (Google Mobile Ads SDK). Google’s User Messaging Platform (UMP) manages consent messages and ad privacy choices.

Advertising services may process IP addresses and approximate location inferred from them, device or app identifiers, ad impressions and clicks, performance and crash/diagnostic data, and consent status. Purposes may include delivering and measuring ads, analytics, troubleshooting, and preventing abuse. Google’s policies and those of applicable ad partners shown in the consent interface apply.

The current app requests non-personalized ads, disables Google Publisher first-party ID, and does not request tracking permission for access to IDFA. Non-personalized advertising can still involve the data processing described above. AI account details, API keys, sign-in sessions or tokens, and usage are not provided to ad requests or the advertising SDK.

Where required, you can make choices in the consent form. When Ad privacy choices is available in app settings, you can reopen it to change your choices or withdraw consent. UMP determines whether ads may be requested. If consent verification fails and ads cannot be requested, ads are omitted; service connections and usage lookup remain available.

Learn more: Google Privacy Policy · How Google uses information from partner apps · Google advertising SDK data disclosure.

Connected services and sign-in providers handle authentication and usage requests directly. Google and applicable ad partners handle advertising requests. These services may process information on servers outside your country, including in the United States. Consult each provider’s policy and consent disclosures for processing locations, retention, and rights requests. The operator does not aggregate AI credentials or usage data for sale or disclosure to others.

5. Retention and deletion

  • Usage history: Each successful refresh prunes history to the preceding 90 days, subject to a record-count cap. This cleanup runs only after a successful foreground or background refresh. Use Delete saved history in settings to remove history while keeping current connections and the latest readings.
  • API connections: Disconnecting in settings or service details deletes the saved key, latest usage, and history for that connection from the app. To revoke a key at the provider itself, revoke it separately through that provider.
  • Codex and Claude: Disconnecting removes that service’s saved usage, history, and in-app web sign-in data. Clear this saved web login on the sign-in screen clears only web sign-in data. It does not delete the provider account or sign-ins in other apps.
  • Latest readings and preferences may remain on the device until changed or removed. Uninstalling alone is not guaranteed to remove every Keychain item; disconnect services before uninstalling. Manage backup copies through your backup service.
  • Retention and deletion of data held directly by Google or AI providers are governed by those providers. Contact them for deletion requests. The operator cannot remotely access or erase data stored only on your device.
